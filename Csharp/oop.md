# 程序導向 與 物件導向

### 程序導向 (Procedural)
* **核心思維**：以**「動作與流程」**為中心（食譜），關注程式要執行什麼步驟。
* **問題**：資料與函式分離，容易導致程式碼互相牽連、維護困難。

### 物件導向 (OOP) Object-Oriented Programming

* **核心思維**：以**「角色與職責」**為中心（團隊分工）。
* **主要優勢**：將**資料（屬性）**與**處理資料的行為（方法）**打包成獨立的物件。
* **思考邏輯**：把「檢查規則」的程式碼，寫在資料擁有者的「類別裡面」。不過有點反邏輯...，因為通常都使用者為主體去動受詞，結果在程式變成car.Wash()，好像車子自己去洗自己。應該這樣看，在 OOP 的世界裡，你建立的每一個物件（Car、BankAccount），都是實體了，是「專門管理該資料的櫃檯」。像玩具總動員？懂嗎，Car.Wash()，是說請Car去把自己洗乾淨；

2.什麼要當作 Class？什麼不要？
判定要不要獨立成一個 Class，關鍵在於：「這項資料是不是一個獨立的『實體』，且身上有沒有包含多個屬性或專屬邏輯？」Drink 應該是 Class：因為「飲料」不是單純的一個數字或字串，它同時包含了：Name (名稱)、Price (價格)、Stock (庫存)，甚至還有專屬邏輯（如：ReduceStock() 檢查庫存是否足夠）。



#### 物件導向的特徵or支柱（Four Pillars）
物件導向語言（如 Java, C#, Python）提供了這些功能與工具，但必須由Enginner自己寫出來，程式才會具備這些特性。
- 抽象化(Abstraction)：過濾掉不需要的細節，然後在程式裡定義出 CLASS
- 封裝(Encapsulation)：自己的資料自己管，將變數保護起來（如 private set），僅透過公開方法（Method）或屬性（Property）進行讀寫與邏輯檢查。

## 核心對比

| 對比項目 | 程序導向 (Procedural) | 物件導向 (OOP) |
| :--- | :--- | :--- |
| **思考邏輯** | 程式要執行什麼步驟？ | 系統有哪些角色？各自負責什麼？這資料是誰的，誰最了解這資料的 |
| **資料與行為** | 資料與函式分離 | 資料與行為封裝在一起 |
| **真實世界比喻** | 自動化流水線機關 | 麥當勞餐廳 |
| **維護與擴充** | 修改流程容易動到全部 | 修改特定類別，其他模組不受影響 |
| **DRY 原則** | 邏輯容易重複散落 | 邏輯集中在類別方法中，重複呼叫 |
